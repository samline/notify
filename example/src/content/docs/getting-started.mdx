This guide takes you from installation to a working success, error, and promise notification. By the end, you will know where the toaster lives, when it must be mounted, and which imports belong in your client entrypoint.

## Prerequisites

- Node.js 20 or newer for package tooling.
- A browser target with ES2020 support.
- A client entrypoint that runs after the DOM is available.

## Mount and notify

Import the stylesheet once in a client entrypoint, then mount the singleton after a browser `document.body` exists.

```ts title="app.ts"
import { createToaster, toast } from '@samline/notify'
import '@samline/notify/styles.css'

createToaster({
  position: 'bottom-right',
  richColors: true,
  theme: 'system'
})

toast.success('Saved')
toast.error('Could not save', {
  description: 'Try again in a moment',
  closeButton: true
})

toast.promise(
  () =>
    new Promise<{ name: string }>((resolve) => {
      window.setTimeout(() => resolve({ name: 'Sam' }), 800)
    }),
  {
    loading: 'Loading profile',
    success: (profile) => `Welcome, ${profile.name}`,
    error: 'Could not load profile'
  }
)
```

`createToaster()` appends one `<ol>` to `document.body`. Repeated calls update that singleton instead of adding another container. Toasts default to 4 seconds, pause while hovered or focused, and loading toasts remain until updated or dismissed.

:::note[Server rendering]
Importing `@samline/notify` and `@samline/notify/browser` is safe without a DOM. `createToaster()` and `mountToaster()` are DOM-only: call them from client lifecycle code after `document.body` exists.
:::

## No bundler

This complete page places the IIFE before the code that uses it, at the end of `<body>`. No `defer` ordering race is involved.

```html title="index.html"
<!doctype html>
<html lang="en">
  <head>
    <meta charset="utf-8" />
    <meta name="viewport" content="width=device-width" />
    <title>Notify example</title>
    <link rel="stylesheet" href="https://unpkg.com/@samline/notify@latest/dist/styles.css" />
  </head>
  <body>
    <button id="save" type="button">Save profile</button>

    <script src="https://unpkg.com/@samline/notify@latest/dist/browser/global.global.js"></script>
    <script>
      document.querySelector('#save').addEventListener('click', () => {
        window.Notify.toast.success('Profile saved')
      })
    </script>
  </body>
</html>
```

The IIFE creates `window.Notify` and auto-mounts the singleton. Pin `@latest` to a published version in production. See [Browser builds](/notify/reference/browser/) for CSP and self-hosting guidance.

## One shared state

Use `createToaster()` for normal application usage. The advanced `mountToaster(root, options?)` function creates another renderer, but it does **not** create another toast channel: direct mounts subscribe to the same global `ToastState`, receive the same published events, and can duplicate notifications. The legacy `id`/`toasterId` fields only filter that shared state; they do not isolate history, counters, subscriptions, or lifecycle. Do not use duplicate mounts as an application routing system.
