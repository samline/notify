## Promise with a timer

```ts
import { createToaster, toast } from '@samline/notify'
import '@samline/notify/styles.css'

createToaster({ richColors: true })

const operation = toast.promise(
  () =>
    new Promise<{ name: string }>((resolve) => {
      window.setTimeout(() => resolve({ name: 'Quarterly report' }), 900)
    }),
  {
    loading: 'Creating report',
    success: (report) => ({
      message: `${report.name} is ready`,
      description: 'The download can begin.',
      action: { label: 'Download report', onClick: () => console.log('Download started') }
    }),
    error: (reason) => ({
      message: 'Report failed',
      description: reason instanceof Error ? reason.message : 'Try again later'
    })
  }
)

const report = await operation.unwrap()
```

The loading id is reused for the settled toast. `unwrap()` returns the original value; see [Promise API](/notify/reference/promises/).

## Manual same-id update

```ts
import { toast } from '@samline/notify'

const id = toast.loading('Uploading invoice')

window.setTimeout(() => {
  toast.success('Invoice uploaded', { id, duration: 6000 })
}, 1000)
```

Loading has no timer. Updating the same id changes the existing record and starts the success timer.

## Undo action

```ts
import { toast } from '@samline/notify'

toast('Message archived', {
  type: 'action',
  duration: 8000,
  action: {
    label: 'Undo archive',
    onClick: () => console.log('Message restored')
  },
  cancel: {
    label: 'Dismiss'
  }
})
```

Both controls are native buttons and close by default. Set `closeOnClick: false` only when the toast must remain available after activation.

## Safe custom DOM

```ts
import { toast } from '@samline/notify'

toast.custom(
  (container) => {
    const heading = document.createElement('strong')
    heading.textContent = 'Build complete'

    const detail = document.createElement('span')
    detail.textContent = ' Production assets are ready.'

    container.append(heading, detail)
  },
  { duration: 8000 }
)
```

Custom toasts are unstyled and do not receive a generated close button. Never put untrusted content into `innerHTML`.

## Snapshot without mutation leaks

```ts
import { toast, type ToastT } from '@samline/notify'

const active: ToastT[] = toast.getToasts()
const history: ToastT[] = toast.getHistory()

active.splice(0) // Does not mutate ToastState.
const first = history[0]
if (first?.action) first.action.label = 'Local copy'
```

Arrays, toast items, and nested action/cancel objects are cloned. Callback functions, promise objects, and custom DOM references remain references.

## Typed low-level event narrowing

```ts
import { ToastState, type RenderableOrFactory, type ToastToDismiss } from '@samline/notify'

const fallback: RenderableOrFactory = () => 'Notification'

const unsubscribe = ToastState.subscribe((event) => {
  if ('dismiss' in event) {
    const dismissed: ToastToDismiss = event
    console.log('Dismissed', dismissed.id)
    return
  }

  console.log('Created or updated', event.title ?? fallback)
})

// Call during integration cleanup.
unsubscribe()
```

These imports are valid root exports. Low-level subscribers run synchronously, so keep them fast and do not throw.

## Theme and hotkey update

```ts
import { createToaster } from '@samline/notify'

const toaster = createToaster({
  theme: 'system',
  hotkey: ['altKey', 'KeyT'],
  style: { '--border-radius': '12px' }
})

toaster.update({
  position: 'top-right',
  closeButton: true,
  closeButtonAriaLabel: 'Dismiss notification'
})
```

`update()` preserves omitted options and returns the same controller.

## Reset for a test

```ts
import { createToaster, resetToasts, toast } from '@samline/notify'

const toaster = createToaster()
toast.success('First test')

resetToasts()

// The existing renderer is still subscribed; the next generated id is 1.
toast.info('Second test')

toaster.destroy()
```

Use `resetToasts()`, not `resetToastState()`, when a mounted renderer must remain usable.

## Teardown and explicit remount

```ts
import { createToaster, destroyToaster, toast } from '@samline/notify'

createToaster()
toast.info('Before teardown')
destroyToaster()

// Destruction does not auto-remount.
createToaster({ position: 'bottom-left' })
toast.success('After remount')
```

For framework lifecycle examples, see [Framework integrations](/notify/reference/frameworks/).
