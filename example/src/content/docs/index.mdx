`@samline/notify` exposes a `toast` factory plus a small toaster-controller surface, renders DOM directly with a vanilla renderer, ships a typed IIFE bundle for `<script>` tags, and keeps every transition and animation in CSS. It is the only runtime entrypoint since v3.0.0 — no React, Vue, or Svelte wrapper, no virtual DOM, just one factory and a focused method surface. (Patch releases like v3.0.1 are API-compatible.)

## Why @samline/notify?

- **Vanilla-first** — Works with native HTML pages, embedded scripts, static sites, and server-rendered templates.
- **Two entrypoints** — Import the ESM factory for bundlers, or drop a single `<script>` for the browser global (`window.Notify`).
- **Data-attribute driven** — Every visual state is a CSS rule reading a `data-*` attribute. Theme by overriding CSS variables, no inline JS styles.
- **Same-id updates** — `toast.promise()` and manual `toast({ id })` updates re-render the existing `<li>` in place, so the DOM never grows past the visible stack.
- **Auto-dismiss + swipe** — Per-toast `setTimeout`, hover-pause, swipe-to-dismiss for corner positions, `visibilitychange` to pause while the tab is hidden.
- **Zero runtime dependencies** — Tiny footprint, ESM + CJS bundles, ships its own types, and a IIFE for `<script>` tags.
